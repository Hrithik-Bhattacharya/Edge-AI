Edge AI framework: BLERP - Bandwidth, Latency, Economics, Reliability, Privacy;

Bandwitdh: sensors produce more data than networks can carry cheaply --> reduction in amt of data being transmitted
Latency: rtos ensures worst case latency is guarded. RTOS is used in systems like aircrafts and cars but not in laptops. Edge devices neccesarilly need low latency to work properly

weights during training - volatile [flash]
weights during inference - non volatile [RAM]
inputs during training - preferably volatile
basic idea: Anything that changes during execution will be stored in volatile memory whereas anything that remains constant is preferred to be stored in non volatile space [i.e. flash]
Five patterns for splitting the work.
1 · On-device
2 · Edge filter
3 · Cascade
4 · Gateway
5 · Split model

1. On device - B[saved bandwidth], L[Round trip latency {to and from cloud} is saved], E[cannot comment so not considered- it may be applicable for a specific use case], R [high reliability], P [Privacy is mentioned];

2. Edge filter [e.g. voice assistant] - if the data is relevant, send it to the cloud; The edge filter identifies what data must go to the cloud;
	What BLERP is relevant: Bandwidth [saved], Latency [cant comment, subject to cloud availability; however the irrelevant data is not sent to cloud and that latency is reduced], Economics [if something is bad data, dont waste time analysing it, but if something is good we send it to cloud for additional processing; Transmission of data from edge to cloud is less cost due to avoidance of redundant data... however hardware and total infra cost remains the same; Only transmission cost is saved]

3. Cascade: input -> tiny model (edge; always on and consumes power constantly) -> big model or processor (only turned on when needed and consumes power only when turned on) -> cloud
	E.g. - A microcontroller handles the initial work and behaves like a tiny model which may sometimes wake up the microprocessor (bigger model); It may be noted that both the tiny and large models can be on the same chip (e.g. recent Arduino chips with dual microcontroller and microprocessor);
BLERP: Along with B,L, E++ i.e. it reduces latency and cloud costs to a much larger extent and allows for local processing to save time and cost; economically better solution to edge filters);

4.Gateway: multiple small sensors -> shared gateway / processing unit ->alarm, cloud (bidirectional arrow);
Main difference here is that it does the feature extraction or relations between various sensors data. Sensors have to be related to each other such that there exist features that the shared brain can identify therefore choice of sensors is necessary such that they are similar in nature;
Applications - systems like EV, Sensor fusion approach, Industrial systems

5.Split computation: Split the model into two parts and keep some of it on the cloud;
Feature extraction or feature map is built on the edge device and that is sent to the cloud for the training part;
Active current research and complicated to maintain; not much has been inferred yet;
